# ADR-0024: 固定した物体の説明はローカルLLM (Ollama) で生成する

- ステータス: 承認済み
- 記録日: 2026-08-30
- 関連: [ADR-0003](0003-label-localization.md), [ADR-0010](0010-client-side-display-policy.md), [ADR-0019](0019-key-binding-policy-v2.md)

## 文脈

単体鑑定で `Enter` により対象を固定できても、利用者が得られる情報は枠と
ラベル(英語ラベル + 日本語名、[ADR-0003](0003-label-localization.md))だけである。
「鑑定」の名に沿うなら、それがどんな物かという説明まで出てほしい。

説明を生成するには言語モデルが必要だが、XRグラス上の対話的な用途であり、
待ち時間・コスト・オフライン性が問われる。実機環境は 24GB RAM の Apple M4 で、
Ollama 0.33.2 が `localhost:11434` で稼働できる。

## 決定

- `POST /explain` を追加する。物体ラベル(英語ラベル + 和名)を受け取り、
  説明文を**ローカルLLM (Ollama / gemma4:e4b)** で日本語の 2〜3 文として生成して返す。
  HTTP クライアントは stdlib の `urllib` とし、新規の pip 依存は追加しない。
- フロントは固定の瞬間に説明ウィンドウを開いて `/explain` を呼ぶ。開いている間は
  `Enter` / `Esc` を「ウィンドウを閉じる」に専任にする
  ([ADR-0019](0019-key-binding-policy-v2.md) の「開いている画面がキーを吸収する」の延長)。
- 同一ラベルの説明文は、サーバ(`_explain_cache`)とフロント(`explainCache`)の
  両方でキャッシュし、再生成しない。
- 鑑定文は**異世界アニメの「鑑定」モチーフに合わせた人物像**(無口な職人鑑定士)
  で生成する。プロンプト直書きであり、モデルのファインチューニングや
  Modelfile によるカスタムモデル化はしない。

## 理由

- **ローカルLLMにした (クラウドAPIでなく)**: ランニングコストが無料で、オフラインで
  動く。鑑定するたびに API 利用料金が発生する設計は避けたかった。OpenRouter 等の
  クラウドAPIは品質面の候補にはなるが、この点で不採用。
- **異世界の鑑定士として語らせる**: この作品のモチーフは異世界アニメの「鑑定」であり、
  素の百科事典調の説明文では世界観が壊れる。人物像(無口な職人鑑定士)と口調を
  プロンプトで与え、鑑定のつぶやきとして出させる。
- **2分岐ルール (素直に鑑定 / 遺物として扱う)**: 異世界の住人は電気・機械を知らない。
  そのまま PC や携帯の正体を説明させると世界観が破綻するため、科学技術の産物は
  「古代文明の遺物」「謎の物体」として正体を明かさず観察と推測だけで語らせる。
  一方、傘や杯・剣など昔から存在しうる道具まで遺物にすると演出過剰になる
  (初版プロンプトで傘が「古代文明の遺物めいた気配」となる事象を確認)ため、
  こちらは素直に用途と価値を語らせる。
- **プロンプト直書きにした (Modelfileでなく)**: 人物像の変更がコードレビューと
  git 履歴で追える。セットアップ手順も `ollama pull` のまま増えない。
  gemma4:e4b は人物像の演技に十分で、カスタムモデル化の利益が手間に見合わない。
- **DeepSeek-V4-Flash-0731 は候補から外れた**: Q4 量子化でも 155GB RAM が必要で、
  24GB M4 では動かせない。
- **Qwen3.6 35B も候補から外れた**: サイズの割に応答が遅く、鑑定の待ち時間として
  成立しないため。
- **gemma4:e4b を採用**: 実測で `think:false` + 61 トークン生成が約 7.5 秒。
  説明 2〜3 文の用途には十分な速度で、24GB RAM で動く。
- **`think:false` を必ず付ける**: 付けないと英語の思考トレースが本文に混ざり、
  生成時間も延びる。応答品質と速度の両方に効く必須設定。
- **同一ラベルはキャッシュ**: 生成は秒単位の処理で、同じラベルの説明が変わる理由が
  ない。ラベルは COCO/LVIS 語彙なので種類は有限で、キャッシュが肥大化しない。
- **入力はラベルのみ (画角情報は渡さない)**: 説明の要求は「この名前の物とは何か」に
  留める。画角の個体の見た目まで説明させると、画像入力に対応したモデルと契約が
  変わり、生成も遅くなる。

## 結果

- 固定の瞬間に説明ウィンドウが出る。初回生成は実測 **約 7.5 秒**、以後は同一ラベル
  ならキャッシュから即座に表示される。鑑定士の口調は実測で約 50 トークンに収まり、
  生成時間も素の説明文と同等である。
- **引き受けた制約**: Ollama の起動が必要。未起動・タイムアウト時は 503 を返し、
  フロントは失敗メッセージを出す(固定自体は継続する)。
- **引き受けた制約**: 鑑定文はラベル由来の一般論で、画角に見えている個体の特徴
  (色・汚れ・状態)は含まれない。
- **引き受けた制約**: どちらの分岐に落ちるかはモデルの判断次第で、境目の物体
  (時計・眼鏡など)は素直に鑑定されたり遺物扱いされたり揺れる。
- **引き受けた制約**: キャッシュはプロセス内のみ。サーバを起動し直すと説明文は
  再生成される。
