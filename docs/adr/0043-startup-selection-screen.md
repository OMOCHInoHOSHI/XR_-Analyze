# ADR-0043: 起動画面でカメラと検出モデルを選んでから検出を始める

- ステータス: 承認済み
- 記録日: 2026-11-19
- 関連: [ADR-0004](0004-config-resolution-order.md), [ADR-0005](0005-camera-selection.md), [ADR-0006](0006-single-background-pipeline.md), [ADR-0035](0035-camera-auto-reconnect.md), [ADR-0040](0040-default-model-yoloe.md), [ADR-0041](0041-windows-camera-support.md), [ADR-0042](0042-windows-exe-packaging.md)

## 文脈

カメラとモデルは環境変数 (`CAM_INDEX` / `CAM_NAME` / `MODEL`) でしか選べず、
どの index が何のカメラかは `list_cameras` を別に実行して調べる必要があった。
exe ([ADR-0042](0042-windows-exe-packaging.md)) はダブルクリックで起動するので
環境変数を付けにくく、PC ごとにカメラの並び (内蔵・外付け・仮想カメラ) も違う。

## 決定

- サーバは検出パイプラインを**起動時には作らない**。`/` は起動画面 (`frontend/setup.html`)
  を返し、そこで次を選んでから `POST /setup/start` で検出を始める。
  - **カメラ**: 実際に開いて確かめた一覧。名前 (macOS / Windows)、実際に得られた
    解像度、見分け用の縮小画像を添える。
  - **検出モデル**: 既知の YOLO 検出モデル (推奨順。未取得なら「初回にダウンロード」)
    と、手元にある `.pt` (`DATA_DIR` 直下と `DATA_DIR/models/`)。一覧に無い名前・パスも入力できる。
- 初期選択は従来の優先順位に従う。カメラは `CAM_INDEX` 明示 > `CAM_NAME` の名前一致 >
  最初に映ったカメラ、モデルは `MODEL` (既定 `yoloe-11l-seg-pf.pt`)。
- 立ち上げの進み具合は `selecting → starting → running` (失敗なら `error` で選び直せる)
  を `/setup/status` で返す。モデルの読み込み (初回はダウンロード) とカメラのオープンは
  背景スレッドで行う。`running` になれば `/` は従来の画面を返し、起動画面はそこへ移る。
- `SETUP=0` または `--no-select` で、従来どおり環境変数の設定ですぐ検出を始める。

## 理由

- **ブラウザの画面にした**: 操作はもともとブラウザで行うので、起動から鑑定まで
  一つの画面で完結する。縮小画像を出せるのでカメラを見分けやすい。
  tkinter の窓 (ブラウザと別の窓が増える) や、コンソールでの番号入力 (画像を出せない)
  も検討したが採らなかった。
- **パイプラインを後から作る**: 既存のハンドラは `pipeline is None` を「起動中」として
  扱う作りなので ([ADR-0006](0006-single-background-pipeline.md))、作る時期を遅らせる
  だけで既存の画面・API を変えずに済む。
- **一覧を作るときにカメラを実際に開く**: 名前の列挙だけでは「開けるか」「映るか」が
  分からない。代わりに一覧づくりに数秒かかるので、結果は取っておき、
  「再読み込み」のときだけ調べ直す。検出が動いている間はカメラを取り合わないよう、
  一覧づくりを断る (409)。
- **選んだカメラの名前を再接続にも使う**: 名前が分かれば、抜き差しで index が
  ずれても名前で追従する ([ADR-0035](0035-camera-auto-reconnect.md))。名前が
  分からない環境では、選んだ index だけを試す。

## 結果

- 環境変数を知らなくても、起動画面でカメラとモデルを選べるようになった。
- 開発時の `python -m backend.server` も既定で起動画面を経由する。従来の即時起動が
  要る場合 (自動起動・計測など) は `--no-select` を付ける。
- 稼働中にカメラやモデルを切り替える機能は無い。選び直すにはサーバを再起動する。
- 推論デバイス (`DEVICE`) は選ばせず、表示するだけにした (自動判定が妥当なため。
  [ADR-0009](0009-inference-device-selection.md))。

## 追記 (2026-11-20): カメラはドロップダウンで選ぶ

カメラの一覧は当初、縮小画像つきのカードを並べて選ばせていたが、ドロップダウン
(`<select>`) に改めた。項目には名前・index・実際の解像度を出し、選んでいるカメラの
縮小画像だけを下に1枚出す。カメラの数が増えても画面の高さが変わらず、キーボードでも
選びやすい。

## 追記 (2026-11-23): 開始後に再読み込みが止まらない不具合

「開始を押すと再読み込みが繰り返され起動しない」という報告があった。2026-11-20 の
「無限ループして落ちた」もこれだったとみられる。

- **原因**: `/` は同じ URL のまま、開始前は起動画面、開始後は本画面を返す。それなのに
  キャッシュの指定を付けていなかった。ブラウザは `Last-Modified` から鮮度を推定する
  (経過時間の1割。ファイルが3日前なら約7時間)。その間はサーバに問い合わせず、古い
  起動画面を出す。起動画面は「稼働中」と見て `/` へ移り、またキャッシュの起動画面が出る。
  ヘッドレス Chrome で再現し、ページの読み込みが4万回以上繰り返されることを確認した。
  curl での確認ではキャッシュが効かないので気づけなかった。
- **対処**:
  - `/` と `/setup` は `Cache-Control: no-store` で返す。
  - `/static/*` は `no-cache` で返す (ETag で確かめるだけなので、変わっていなければ 304)。
  - 起動画面から本画面へ移るときと、ブラウザを自動で開くときは、`/?t=<時刻>` と毎回
    別の URL にする。この修正より前の版のキャッシュが残っていても使われない。
  - 起動画面は、稼働中なのに15秒以内に3回戻ってきたら、移るのをやめて Ctrl+F5 を
    案内する。原因が何であれ、ループが止まらなくなることは防ぐ。
