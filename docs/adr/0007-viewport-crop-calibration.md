# ADR-0007: グラスとの視界合わせはカメラ側の中央クロップで行う

- ステータス: 承認済み
- 記録日: 2026-08-18
- 関連: [ADR-0002](0002-detection-streaming-contract.md), [ADR-0006](0006-single-background-pipeline.md), [ADR-0008](0008-calibration-persistence.md)

## 文脈

カメラをスマートグラス (XREAL Air 2 Pro) に取り付けると、グラス越しの肉眼の視界と
カメラ映像の画角・位置がズレる。実用するにはこのズレを詰める調整が要る。

また、カメラは逆さに取り付けているため向き補正 (既定で 180° 回転) も必要で、
補正とクロップの適用順序を決める必要がある。

## 決定

- 視界合わせは**カメラ読取時点の中央クロップ (デジタルズーム) + 切り抜き中心のオフセット**で行う。
- 向き補正 (flip) を**先**に、クロップを**後**に適用する。
- オフセットは**フレーム全体に対する正規化値**で表す。
- クロップ後に**リサイズはしない**。
- 値は `clamp_view` で実効範囲に丸めてから保持する。

## 理由

- **カメラ読取の時点で処理する**: 推論・MJPEG 映像・検出座標がすべて同じ向き・
  同じ切り抜きになる。表示側で補正すると「映像は動いたが枠は動かない」事故が起きる。
- **flip → crop の順にする**: 画面に表示された向きを基準にオフセットが効く。
  逆さ付けカメラでも「画面上の右 = +x」となり直感と一致する。逆順だと、
  補正後に上下左右が入れ替わって調整キーの向きが反転する。
- **オフセットを全体比にする**: 「残り余白に対する比率」にすると、ズーム倍率を変えた
  ときにオフセットの意味そのものが変わり、調整をやり直すことになる。全体比なら
  ズームを先に決めてからオフセットで詰められる。
  パン可能な範囲はズームから決まる: `(zoom - 1) / (2 * zoom)`
  (1.0 でパン不可、1.5 で約 ±0.17、2.0 で ±0.25)。
- **リサイズしない**: `IMG_SIZE` でどのみち縮小されるため不要な処理コストであり、
  切り抜くほど残った被写体の実効解像度はむしろ上がる。
- **保持する値をクランプする**: `crop_zoom` は幾何的にオフセットをクランプするため、
  実効範囲を超えた生の値を保持し続けると、HUD 表示や保存される確定値が実際の見た目と
  ズレる。ズームを変えると実効範囲そのものが変わるので、値を更新するたびに
  ズームとオフセットを三つまとめて通す。

## 結果

- ズーム 1.0 未満は「余白を足す」意味になり成立しないため 1.0 にクランプする。
  1.0 では余白が無いのでパンもできない。
- 調整はブラウザから `POST /calib` に差分 (`dzoom` / `dx` / `dy` / `reset`) を投げる形なので、
  Unity 等の他クライアントからも同じ調整ができる。フロントは自前で値を持たず、
  確定値を `/ws` の `view` で受け取る ([ADR-0002](0002-detection-streaming-contract.md))。
- `clamp_view` の丸めで `-0.0` が生まれるため (`max(-0.0, 0.0)` は `-0.0` を返す)、
  `+ 0.0` で正規化して HUD に `-0.0` と表示されるのを防いでいる。
- `Camera.open()` のウォームアップは生の `cap.read()` ではなく `self.read()` を使う。
  生の読取だと flip / crop を通らず、直後に `actual_size` を見るとクロップ前の
  サイズが返り、`source_size` が実態と一致しなくなるため。
