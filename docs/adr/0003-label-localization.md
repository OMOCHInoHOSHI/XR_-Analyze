# ADR-0003: 英語ラベルを契約に保ち、日本語表示名を併送する

- ステータス: 承認済み
- 記録日: 2026-08-18
- 関連: [ADR-0002](0002-detection-streaming-contract.md)

## 文脈

表示は日本語にしたい。一方でクラス名はモデル由来の英語であり、クライアント間で
共有される識別子でもある。

さらに YOLOE のプロンプトフリー語彙は約 4585 語あり、`labels_ja_lvis.py` (LVIS 1203) と
手動辞書だけでは網羅できない。網羅を機械翻訳で埋めたいが、機械翻訳は同音異義語
(bat / mouse / tank など) を外しやすい。

## 決定

- `label` (英語) を契約として常に送り、`label_ja` (日本語表示名) を併送する。
  辞書に無い語は `label_ja` も英語のままにする。
- 日本語辞書は **機械翻訳 (`ja_vocab.json`) < LVIS < COCO < 手動 (`EXTRA_JA`)** の
  後勝ちでマージする。
- MJPEG への日本語描画は PIL で行い、日本語フォントが見つからない環境では
  英語 (cv2) にフォールバックする。

## 理由

- **英語ラベルを契約に残す**: クライアント側で条件分岐や絞り込みをするときの識別子が、
  翻訳の揺れで壊れないようにするため。表示名だけを送ると、辞書を更新した瞬間に
  クライアントのロジックが壊れる。
- **機械翻訳を最下位にする**: 網羅性は機械翻訳で稼ぎつつ、キュレーション辞書が必ず
  上書きする構造にすれば、誤訳が最終表示に出にくい。逆順にすると、手で直した訳が
  辞書の再生成で消える。
- **PIL で描く**: `cv2.putText` は日本語を描けない。ただし日本語フォントの有無は
  環境依存なので、無い環境で落とさずフォールバックする。

## 結果

- 語彙の網羅は `dump_vocab` → `build_ja_dict` のオフライン生成で行うため、実行時は
  オフライン・高速のまま保てる。
- `ja_vocab.json` は生成物である。気になる訳は直接編集するか、`EXTRA_JA` へ追記して
  上書きする運用になる。
- LVIS のクラス名は `"aerosol can/spray can"` のように同義語が `/` で連結されるため、
  照合はフル文字列 → 最初の同義語の 2 段で行う。
- 文字化け (□) が出る環境では `JP_FONT` でフォントを明示する必要がある。
