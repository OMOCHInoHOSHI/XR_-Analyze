# ADR-0025: 鑑定文の読み上げは macOS 同梱の `say` で合成し、方式は差し替え可能にする

- ステータス: 承認済み
- 記録日: 2026-08-30
- 関連: [ADR-0002](0002-detection-streaming-contract.md), [ADR-0010](0010-client-side-display-policy.md), [ADR-0024](0024-llm-object-explanation.md)

## 文脈

[ADR-0024](0024-llm-object-explanation.md) で、固定した物体の鑑定文をローカルLLMに
「無口な職人鑑定士」として語らせるようにした。しかし出力は画面の文字だけで、
利用者は窓を読みに行く必要がある。XRグラスを着けて手元の物を見ている最中に
文字を読ませるのは体験として弱く、鑑定士が声で告げるほうが人物像に合う。

制約は実機の資源である。実機は 24GB RAM の Apple M4 で、YOLO の推論 (MPS) と
Ollama (gemma4:e4b) が既にメモリと計算資源を占めている。ここへ音声合成のために
常駐プロセスをもう一つ載せるのは割に合わない。pip 依存も増やしたくない
([ADR-0024](0024-llm-object-explanation.md) で stdlib の `urllib` に留めたのと同じ理由)。

## 決定

- `POST /speak` を追加する。鑑定文 (ラベル + 本文) を受け取り、**macOS 同梱の `say`
  コマンド**で WAV を合成して `audio/wav` で返す。フロントは鑑定文が出そろった
  時点でこれを取りに行き、`Audio` で鳴らす。
- 合成そのものは `backend/tts.py` に切り出し、`TTS_BACKEND` (`say` / `off`) で
  選ぶ。将来 VOICEVOX 等へ移すときは `tts.synthesize()` の分岐を足すだけで済ませる。
- 声は既定で **`Grandpa` (日本語の老翁の声)**、話速は既定 175 に対し **130** へ落とす。
  どちらも `TTS_VOICE` / `TTS_RATE` で変えられる。

## 理由

- **`say` を採った (常駐エンジンでなく)**: 追加インストールも常駐プロセスも pip 依存も
  ゼロで、都度プロセスを起動して終わる。鑑定文の長さ (50〜100 文字) で実測 0.5 秒
  前後。ボイスの読み込みが要る初回だけ 2.1 秒かかるが、それも一度きりである。
  鑑定文の生成 (実測 7.5 秒) に対して十分小さく、待ち時間の体感を変えない。
  制約を厳密に満たす選択肢はこれだけだった。
- **VOICEVOX ENGINE を採らなかった**: キャラクター音声の完成度は最も高いが、
  既定ポート 50021 の HTTP サーバを常駐させる前提であり、macOS では GPU コアが
  非対応で CPU 合成に限られる。YOLO と Ollama が動く同じ Mac に CPU 推論エンジンを
  もう一つ抱えることになる。加えてキャラクター音声は「VOICEVOX:話者名」の
  クレジット表記が条件で、表記なしの商用利用は別途ライセンス契約が要る。この段階で
  引き受ける理由がない。AivisSpeech も同じく常駐エンジン前提のため同様。
- **Style-Bert-VITS2 も外れた**: pip 依存が増えるうえ本体が AGPL-3.0 で、ネットワーク
  越しに提供する形だと改変部分のソース開示義務が生じうる。声質のために背負う
  ライセンス条件として重い。
- **ブラウザの Web Speech API 単独にしなかった**: サーバを一切変えずに済む最軽量案だが、
  `speechSynthesis.getVoices()` の中身がブラウザで揃わない (Chrome は Google 製の
  独自ボイスを優先して返し、Safari は OS のボイスを返す)。声が環境で変わると人物像が
  再現しない。サーバ側で合成すれば、Web・Unity・Android のどのクライアントから
  読んでも同じ声になり、[ADR-0002](0002-detection-streaming-contract.md) の
  「配信側が契約を持つ」形とも揃う。
- **`Grandpa` を既定にした**: 実機の `say -v '?'` では日本語ボイスが Kyoko / Grandpa /
  Grandma / Eddy / Flo / Reed / Rocko / Sandy / Shelley の 9 種あり、この中で
  `Grandpa` の老翁の声が「無口な職人鑑定士」([ADR-0024](0024-llm-object-explanation.md))
  に最も近い。話速を 130 まで落とすのは、口数の少ない鑑定士が重々しく告げる調子に
  寄せるため。好みが割れる部分なので環境変数で変えられるようにした。
- **本文は標準入力 (`-f -`) で渡す**: 鑑定文は LLM の生成物で内容を制御できない。
  引数に置くと `-` で始まる文がオプションと解釈されうる。`-f -` なら本文として
  扱われることを実測で確認した。`shell=True` は使わない。
- **一時ファイルを経由する**: `say -o -` (標準出力) は
  `Opening output file failed: fmt?` で失敗する。標準出力へ直接流す道がないため、
  `tempfile` に書かせて読み直す。
- **音声キャッシュには件数上限を置いた**: 1 件が 0.5〜1.0MB (鑑定文 50〜100 文字を
  LEI16@22050 で合成した実測値) あり、鑑定文のキャッシュのように無制限にすると
  LVIS 語彙で数 GB に届く。ラベル単位の LRU で 32 件に抑える。同一ラベルなら鑑定文も
  同じなので、キーはラベルだけでよい。
- **読み上げの失敗は表示に影響させない**: 音声は補助であり、鑑定そのものではない。
  鑑定文の生成失敗はトーストで知らせる ([ADR-0024](0024-llm-object-explanation.md))
  が、読み上げの失敗は黙って諦める。音が出ないことに気づくのは音を待った人だけで、
  文字は既に出ている。

## 結果

- 固定 → 鑑定文が窓に出る → 約 0.5 秒後に鑑定士の声で読み上げが始まる。同一ラベルは
  音声もキャッシュから返るため、2 回目以降は即座に鳴る。
- **引き受けた制約**: macOS 限定。`say` が無い OS では `TTS_BACKEND` の既定が `off` に
  なり、無音のまま従来どおり動く。
- **引き受けた制約**: 声はシステムボイスの範囲で、VOICEVOX 等のキャラクター音声ほどの
  作り込みはできない。人物像の再現度は「老翁の声をゆっくり」までである。
- **引き受けた制約**: 読み上げの開始は鑑定文の生成完了後なので、固定から声が出るまで
  実測で約 7.5 秒 + 0.5 秒。文が出る前から喋らせることはできない。
- **引き受けた制約**: 再生はブラウザの自動再生ポリシーに従う。`Enter` の操作を
  起点にしているため通常は鳴るが、拒否された場合は黙って諦める。
- **引き受けた制約**: 音声キャッシュは 32 件で最大 32MB ほどを占める。`/speak` は
  本文の長さを制限していないため、鑑定文より長い文を投げれば 1 件はさらに大きくなる。
  `HOST` 既定の 127.0.0.1 でローカルからしか叩けない前提に依存しており、この点は
  `/explain` ([ADR-0024](0024-llm-object-explanation.md)) と同じ信頼モデルである。
- **引き受けた制約**: 音声キャッシュはプロセス内のみ。サーバを起動し直すと再合成する。
