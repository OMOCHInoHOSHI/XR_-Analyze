# ADR-0033: 読み上げの待ちは本文の下に帯で示す

- ステータス: 承認済み
- 記録日: 2026-08-30
- 関連: [ADR-0014](0014-box-theme-and-dom-reuse.md), [ADR-0024](0024-llm-object-explanation.md), [ADR-0027](0027-speech-prefetch-during-generation.md)

## 文脈

[ADR-0027](0027-speech-prefetch-during-generation.md) で先読み合成を入れても、
鑑定文が出てから声が鳴るまで 5〜7 秒の待ちが残ることが実測で分かった。合成の
総コストが生成時間を上回るためで、この構成では消せない。

待ちが消せない以上、待っていることを見せる必要がある。最初は見出し
(`.e-head`) の右端に「読み上げ準備中…」を小さく出したが、利用者から
**「まだ待機中だと分からない」**と言われた。薄い文字を隅に置いても、本文を
読んでいる目には入らない。

## 決定

- 待ちの表示を、**本文 (`#e-body`) の下に独立した帯**として出す。
- 文言は **「鑑定士が口を開くまで」**。頭に菱形を付け、末尾に**順に灯る三つの点**を
  置く。
- 声が鳴り始めたら消す。取得に失敗したときも消す。

## 理由

- **待ちを隠さずに示す**: [ADR-0027](0027-speech-prefetch-during-generation.md) で
  待ちをゼロにできないと分かった。消せないものを黙って抱えると、利用者には
  「読み上げが無い」のか「まだ来ていない」のか区別が付かない。区別が付けば、
  待つか窓を閉じるかを選べる。
- **本文の下に置いた**: 鑑定文を読み終えた目が自然に落ちる位置である。見出しは
  対象名と閉じ方を示す場所で、本文を読み始めたあとは視線が戻らない。前回そこへ
  置いて気づかれなかったのは、位置の問題が大きい。
- **動く印を付けた**: 静止した文字は「固まっている」とも読める。点が順に灯って
  いれば、待っている最中だと動きで分かる。`prefers-reduced-motion: reduce` では
  止める ([ADR-0023](0023-rotating-mode-wheel.md) と同じ扱い)。
- **鑑定士の言葉にした**: 「読み上げ準備中」は道具の言葉である。この作品は異世界の
  鑑定を題材にしており、語り手は無口な職人鑑定士
  ([ADR-0024](0024-llm-object-explanation.md))。その鑑定士が口を開くのを待って
  いる、という言い方にすれば、待ち時間そのものが演出の側に回る。
- **色を増やさない**: 既存の CSS 変数 (蒼系) だけで作る
  ([ADR-0014](0014-box-theme-and-dom-reuse.md) の意匠に従う)。待ちの表示のために
  新しい色を持ち込むと、画面全体の統一が崩れる。

## 結果

- 鑑定文が出た直後から、声が鳴るまでの間、本文の下に帯が出る。何が起きているか
  画面から分かる。
- **引き受けた制約**: 帯が出る間だけ窓の高さが変わる。声が鳴ると消えるので、
  読んでいる最中に本文の位置が動く。窓は画面中央に固定なので、本文の上端は
  動かない。
- **引き受けた制約**: 待ち時間そのものは変わらない。これは表示の話であって、
  速度の改善は [ADR-0027](0027-speech-prefetch-during-generation.md) の範囲である。
