# ADR-0016: マスクを作らない推論経路を自前で持つ

- ステータス: 承認済み
- 記録日: 2026-08-27
- 関連: [ADR-0002](0002-detection-streaming-contract.md), [ADR-0006](0006-single-background-pipeline.md), [ADR-0009](0009-inference-device-selection.md), [ADR-0017](0017-decoupled-capture-thread.md)

## 文脈

`yoloe-11l-seg-pf.pt` (LVIS 4585 クラスのプロンプトフリー版) を Apple M4 / MPS,
`IMG_SIZE=640` で回すと 1 フレーム 約 197ms、実機で 4fps 前後しか出ない。
`ultralytics` の `predict()` を通した内訳は次のとおり (1280x720 / 検出 12 件)。

| 処理 | 時間 |
|---|---|
| 推論 (バックボーン + ヘッド) | 129.1ms |
| NMS | 41.0ms |
| **マスク生成 (`process_mask`)** | **19.7ms** |
| 前処理・`Results` 構築ほか | 約 7ms |
| 合計 | 197.3ms |

ここで効いているのは次の2点である。

1. **使わないマスクを毎フレーム作っている。** 配信する `Detection` は bbox だけで
   ([ADR-0002](0002-detection-streaming-contract.md))、フロントも枠しか描かない。
   それでもプロンプトフリー版は `-seg` 形式でしか配布されていないため、
   マスク原型の生成 (`proto`)、マスク係数の畳み込み (`cv5`)、マスク復元
   (`process_mask`) がまるごと無駄払いになる。
2. **後処理は検出件数に比例する。** 後処理は検出 0 件で 34.1ms、12 件で 69.3ms
   (1 フレーム全体では 162.6ms → 197.7ms)。「何も映っていないと 6fps、モノを映して
   枠が出ると 4fps に落ちる」という実機の症状はこれである。

一方、Python 自体は律速ではない。上記の内訳のうち Python のグルーコードは 10% 未満で、
残りは PyTorch / Metal の C++・Metal カーネル内にある。実装言語を C 系へ移しても
得られるものは数 % しかない。

## 決定

- `backend/fast_infer.py` を追加し、**`predict()` を経由せずに
  「レターボックス → `model.model(im)` → NMS」だけを行う経路**を持つ。
  マスク経路 (`proto` / `cv5`) は起動時にスタブへ差し替えて計算ごと取り除く。
- 出力が `predict()` と一致すると確認できない構成 (NMS 不要な end2end モデル、
  想定外のヘッド形状) では `fast_infer.build()` が `None` を返し、
  従来の `predict()` 経路にそのまま落ちる。`FAST_INFER=0` でも明示的に戻せる。
- `MAX_DET` の絞り込みは NMS の中で行う。件数を絞ってから後段へ渡す。
- **セグメンテーションモデルに限り**、クラスをまたいだ重なりを IoU
  `DEDUP_IOU` (既定 0.85) で潰す。

## 理由

- **前処理は `ultralytics` の丸め方まで合わせる**: `LetterBox(auto=True, center=True)`
  の `round(dw - 0.1)` まで再現しないと bbox が数 px ずれる。ここを揃えたことで
  bbox は完全に一致する。
- **NMS を自前で持つ**: `ultralytics` の NMS は 4589 列 × 8400 行のテンソル全体に
  対して真偽値マスクの行取り出しを掛ける。こちらはクラス方向の最大値を取ってから
  上位数百件だけを CPU へ送り `batched_nms` に掛ける。結果は同じで、扱う要素数が
  桁で減る。数十件規模の NMS は GPU カーネルの起動待ちより CPU の方が速い。
- **重複排除をセグメンテーションモデルに限る理由**: `predict()` は NMS の後に
  `keep = masks.amax((-2,-1)) > 0` で「復元したマスクが空だった検出」を黙って
  捨てている。マスクを作らない以上このフィルタは再現できず、放っておくと検出が
  **上位集合**になる。実測 (画像 60 枚) では追加された 25 件のうち 18 件が既存の枠と
  IoU 0.85 以上、つまり同じ物体に付いた別ラベル (同じバスに `police van` と `bus`) だった。
  IoU による重複排除でこれを潰すと、追加は 5 件まで減り、**旧経路が出していた検出が
  消えた例は 0 件**だった。マスクを持たない検出モデル (`yolov8n.pt` など) には
  補うべきフィルタが無いので掛けない。そちらは `predict()` と完全に一致する。
- **フォールバックを残す**: この経路は `ultralytics` の内部構造 (`model.model` の
  レイヤ構成、ヘッドの出力形式) に依存する。`requirements.txt` は
  `ultralytics>=8.2.0` と緩いので、更新で前提が崩れうる。崩れたときに黙って
  壊れるのではなく `predict()` へ戻るようにしてある。

## 結果

- 速度は旧経路と交互に 25 回ずつ測って比較した (交互にするのは負荷条件を揃えるため)。

  | 条件 | 旧 `predict()` | 新 高速経路 | 倍率 |
  |---|---|---|---|
  | 検出 12 件 | 193.2ms (5.2fps) | 140.0ms (7.1fps) | 1.38x |
  | 検出 0 件 | 155.9ms (6.4fps) | 114.0ms (8.8fps) | 1.37x |

  実機 (InnoMaker / `CAM_ZOOM=2.4` / 検出 5 件) では **4.4fps 前後 → 6.5fps 前後**。
- 検出結果の一致は画像 60 枚 (2 枚の素材をクロップ・明度・反転で展開) で検証した。
  - `yolov8n.pt` (検出モデル): 60/60 で完全一致。
  - `yoloe-11l-seg-pf.pt`: 消えた検出 0 件、増えた検出 5 件 (旧経路が空マスクとして
    捨てていた別物体)。
- **`ultralytics` の内部に踏み込んだ実装である。** バージョンを上げたら
  `verify.py` 相当の突き合わせを流し直すこと。無言で壊れることはないが、
  フォールバックに落ちて遅くなったことに気付かない可能性はある。起動時に
  どちらの経路を使うかを標準出力へ出しているのはそのためである。
- **CoreML / Apple Neural Engine への書き出しは、速いが未採用。** 判断の材料として
  実測値を残す。後処理まで揃えて交互に 25 回測ると **108.0ms (9.3fps)** で、
  この高速経路 (144.3ms / 6.9fps) より **1.34 倍速い**。採らなかったのは速度以外の
  理由による。

  - プロンプトフリー版のヘッド (`LRPCHead`) は「物体らしさで候補アンカーを絞ってから
    4585 語彙の分類を掛ける」という**動的な形状**の最適化を内蔵している
    (8400 アンカー → 実測 774)。CoreML は動的形状を書き出せないためこの絞り込みが
    失われ、毎フレーム `(1, 4621, 8400)` = 155MB のテンソルを受け取ることになる。
    その集約を MPS でやれば 68ms で済むが、CPU でやると 143.6ms かかり
    (合計 188.9ms) 逆に遅くなる。つまり ANE と MPS の両方を使って初めて勝つ。
  - **fp16 のため信頼度が最大 0.04 ほどずれる。** 検出される物体そのものは
    一致したが、`CONF_THRES` (0.35) や `STAB_APPEAR_CONF` (0.45) の境目付近では
    出る / 出ないが変わりうる。
  - 前処理が正方形 (640x640) のレターボックスに固定され、現行の矩形
    (640x384) と一致しない。
  - 書き出しに `ultralytics` の `LRPCHead.forward` へのパッチが要る
    (`.int()` キャストが CoreML の変換器を通らない)。60MB の `.mlpackage` を
    別途管理することにもなる。
  - モデル内でクラス方向の集約まで済ませて出力を小さくする案も試したが、
    fp16 出力ではクラス番号が 2048 を超えると整数として表現できずラベルが壊れ、
    速度も 309ms と逆に遅くなった (集約が ANE に載らない)。
