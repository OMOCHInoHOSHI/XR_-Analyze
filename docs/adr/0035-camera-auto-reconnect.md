# ADR-0035: カメラ切断を検知して自動で再接続する

- ステータス: 承認済み
- 記録日: 2026-09-04
- 関連: [ADR-0005](0005-camera-selection.md), [ADR-0006](0006-single-background-pipeline.md), [ADR-0017](0017-decoupled-capture-thread.md)

## 文脈

使用カメラ (Innomaker U20CAM) は接触不良を起こすことがあり、稼働中に
USB が外れた状態になる。このとき取得ループは `grab()` の `ok=False` を
10ms 間隔で拾い続けるだけで、**再オープンもログも無い**。
[ADR-0017](0017-decoupled-capture-thread.md) の構成では、取得スレッドが
生フレームを置かなくなるため、MJPEG も `/ws` も最終フレームのまま沈黙する。
クライアント側は直近ペイロードで描き直し続けるだけなので、利用者には
**「画面がフリーズした」ようにしか見えない**。

`_error` は推論例外専用の欄でカメラ由来の切断を記録しないため、
`/healthz` を見ても異常が見えなかった。

## 決定

- 取得スレッド内で `grab()` の**連続失敗が `CAM_FAIL_LIMIT` 回
  (既定 30, 約 1 秒) に達したら切断とみなす**。
- 切断検知時に古いフレーム/検出を捨て、「カメラを再接続しています...」と
  焼き込んだ**プレースホルダーフレーム**を最新フレームとして配信する。
  あわせて `/ws` と `/healthz` に `camera_status`
  (`"ok"` / `"reconnecting"`) を**新設**する。既存フィールドは不変で、
  後方互換である。
- 再オープンは**同一の取得スレッド内**で `release()` → `Camera.try_open()` で
  行う。候補は `reconnect_candidates()` が返す「起動時に開いた index を
  記録したもの」を最優先とし、`CAM_INDEX` を明示していないときだけ
  `CAM_NAME` による**名前再解決**を加える。失敗したら `CAM_RETRY_WAIT`
  (既定 1 秒) 間隔で**無限リトライ**する。
- 復帰するとフレームの供給が再開され、推論は既存の `Event` 待ち設計
  ([ADR-0017](0017-decoupled-capture-thread.md)) により自動で続く。
- `Camera.open()` は起動時の fail-fast (`RuntimeError`) のまま残し、
  稼働中の再試行用に成否を返す `try_open()` に分離する。

## 理由

- **同一スレッド内で再オープンする**: 他スレッドから `VideoCapture` を
  `release()` すると AVFoundation でクラッシュするリスクがある。
  切断検知から再オープンまでを取得スレッドに閉じれば、カメラを触るのは
  常にこのスレッドだけである。
- **無限リトライする**: リトライ回数の上限を設けても、利用者に残る選択肢は
  「サーバを再起動する」だけである。稼働中に刺せば戻る、が挙動として
  一貫しているほうが、グラスを装着したままの運用に向く。
- **名前で再解決する**: USB の抜き差しで index がずれても名前で追従できる。
  接触不良の復帰は抜き差しを伴いやすいので、元の index への固定だけでは
  足りない。
- **`CAM_INDEX` 明示時は名前解決しない**: 起動時の優先順位
  (`CAM_INDEX` 明示 > 名前一致、[ADR-0005](0005-camera-selection.md)) を
  尊重する。明示指定は「この番号以外を開かせたくない」という意思表示なので、
  再接続時にも同じ候補だけを試す。
- **プレースホルダーを配信する**: 最終フレームのまま沈黙していると凍結と
  誤認される。切断中であることが画面に見えていれば、利用者は
  「カメラを確認すればよい」と分かる。

## 結果

- カメラが戻れば表示・検出は自動で復旧する。利用者はカメラが戻るのを待つだけ。
- 既知の限界として、`grab()` が `ok=False` を返すタイプの切断だけが対象である。
  OS/ドライバによっては `read()` がブロックし続けることがあり、その場合は
  検知できず、復帰もブロック解除後になる (実機の抜き差しテストで確認予定)。
- 検知と再オープンのテストを `backend/tests/test_camera_reconnect.py` に
  追加する。
