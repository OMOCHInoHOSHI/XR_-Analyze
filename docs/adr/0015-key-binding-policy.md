# ADR-0015: 鑑定法の切替は 2 ストローク、修飾キー付きは触らない

- ステータス: 承認済み
- 記録日: 2026-08-18
- 関連: [ADR-0010](0010-client-side-display-policy.md), [ADR-0014](0014-box-theme-and-dom-reuse.md)

## 文脈

トップページのキー操作には、調整 (ズーム / 位置 / 保存 / リセット)、表示切替、
鑑定法の切替、意匠の切替が同居している。

数字キーは `0` (調整のリセット) が既に単独機能に使われており、意匠の切替も
`1`〜`6` を単独で使う ([ADR-0014](0014-box-theme-and-dom-reuse.md))。
ここに鑑定法の切替を単独の数字キーで足すと衝突する。

## 決定

- 鑑定法の切り替えは `m` を前置きする **2 ストローク (m → 1/2)** にする。
  待ち状態は **3 秒で自動キャンセル**し、`1`/`2` 以外のキーは**待ち状態の取り消しだけ**に
  使って本来の機能は動かさない。
- **修飾キー (Ctrl / Cmd / Alt) 付きのキーには一切反応しない。**

## 理由

- **数字キーの空間を分ける**: `1`/`2` を単独キーにすると、モードが増えたときに数字キーが
  足りず、意匠の切替とも衝突する。`m` を前置きさせれば数字キーの空間を分けられ、
  調整中の誤爆も防げる。
- **待ち状態中は本来の機能を動かさない**: 動かすと、`m` を押したことを忘れて操作したときに
  「モードが変わり、かつそのキーの機能も走る」という二重の効果が出る。取り消しだけに
  使うほうが予測しやすい。
- **修飾キー付きを無視する**: これらはブラウザ標準のショートカットである。特に macOS の
  `Cmd+0` / `Cmd+=` / `Cmd+-` (ページの拡大縮小) を拾うと、**調整中の値が意図せず
  リセットされる**。

## 結果

- 意匠の切替 (単独の数字キー) と鑑定法の切替は衝突しない。`m` の待ち状態が先に
  処理されるため。
- 意匠のデバッグ機能を削除すれば ([ADR-0014](0014-box-theme-and-dom-reuse.md))、
  単独で使う数字キーは `0` だけになる。それでも 2 ストロークは維持する。
  鑑定法は今後増える見込みがあるため。
- 待ち状態の開閉は鑑定盤の選択肢表示と連動させ、「今 `m` を押している」ことが
  画面から分かるようにしている。
