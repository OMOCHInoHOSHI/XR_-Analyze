# ADR-0023: モードの円盤はカーソルではなく盤そのものを回す

- ステータス: 承認済み
- 記録日: 2026-08-30
- 関連: [ADR-0014](0014-box-theme-and-dom-reuse.md), [ADR-0019](0019-key-binding-policy-v2.md), [ADR-0021](0021-mode-wheel-with-calibration.md)

## 文脈

[ADR-0021](0021-mode-wheel-with-calibration.md) で、円盤は鑑定法(単体鑑定/広域鑑定)
と調整を選ぶモードの盤にすると決めた。項目は円周に等間隔で並び、矢印を押すと
カーソル(強調表示)が円周上を項目からとなりの項目へ移る形だった。

利用者から「右キーを連続で押すと次のものが選択されてほしい」「選択の円自体が
回る感じに、よくある感じの」という要求が出た。カーソルが動くのではなく、盤が
回って選ばれているものが定位置へ来る操作感である。

## 決定

- 項目を**回転体 (`.w-rotor`)** に載せ、`transform: rotate()` で盤ごと回して
  選ぶ。項目自体の `left`/`top` は動かさない。
- **12時に指標 (`.w-mark`, 菱形)** を固定で置く。盤が回っても指標は動かず、
  選ばれている項目は常にこの指標の位置に来る。
- 回転角 (`wheelTurn`) は**足し引きで持つ** (`turnBy()`)。剰余には畳まず、
  一周しても巻き戻らず同じ向きへ回り続ける。
- 盤が回ると項目も一緒に傾くため、`renderWheel()` が各項目を**同じ角度だけ
  逆に回して** (`upright`)、文字を常に水平に保つ。
- 円盤を開くときは `wheelTurn = wheelAngleFor(wheelCursor)` で回転角を直に
  合わせる。閉じている間は `transition` を効かせないため、開いた瞬間に
  回っているところは見せない。
- 回転の遷移は **0.3秒・`cubic-bezier(.22, .61, .36, 1)`**。
  `prefers-reduced-motion: reduce` では、回転も**開くときの拡大 (`wheel-in`)** も
  止める。回転だけ止めても盤を開くたびに動くため、揃えないと意味がない。
- 数字キーによる即確定 ([ADR-0019](0019-key-binding-policy-v2.md)) は変えない。

## 理由

- **盤を回す**: 選ばれているものが常に同じ位置(12時)に来るので、視線を動かさずに
  読める。XR グラスでは盤が視界の中央に出るため、目で追う量が減るほうがよい。
  カーソルが動く方式では、強調がどこに付いたかを毎回探すことになる。
- **12時に指標を置く**: 「ここが選ばれている場所」を固定して示す。盤が回っても
  動かないので、回転の基準点としても働く。
- **角度を足し引きで持つ**: 剰余で持つと、末尾から先頭へ移るときに逆向きへ
  大きく回る。押した向きと盤の回る向きが食い違って見える。
- **文字を逆回転で水平に保つ**: 回転体に載せた項目は親と一緒に傾く。傾いた
  文字は読みにくく、鑑定という題材にも合わない。
- **親ごと回す (`left`/`top` を動かさない)**: 位置を補間すると、項目が円周では
  なく弦を突っ切って動く。回転体を回すほうが円周上の動きとして自然に出せる。
- **開くときは回さない**: 開いた瞬間に盤が回ると、何が起きたのか分からない。
  現在のモードが最初から指標の位置にある状態で開くほうが、開閉のたびに
  「今どこにいるか」を探させずに済む。

## 結果

- 項目の配置が `MODES` から決まるという [ADR-0021](0021-mode-wheel-with-calibration.md)
  の性質はそのまま。項目数を変えても1項目あたりの回転角 (`wheelStep()`) が
  追従する。
- 環の左右の菱形はそのまま装飾として残り、12時は指標 (`.w-mark`) が占める。
- **引き受けた欠点**: 項目数が増えるほど1回の回転角が小さくなり、動きが
  分かりにくくなる (5件で72度)。
- **引き受けた欠点**: 矢印を押すたびに回転体と全項目の `transform` を書き換える。
  盤を開いている間の操作にしか起きないため、影響は小さい。
