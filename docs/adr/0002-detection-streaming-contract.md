# ADR-0002: 検出結果は JSON over WebSocket + 正規化座標を唯一の契約とする

- ステータス: 承認済み
- 記録日: 2026-08-18
- 関連: [ADR-0001](0001-monorepo-layout.md), [ADR-0003](0003-label-localization.md), [ADR-0007](0007-viewport-crop-calibration.md), [ADR-0010](0010-client-side-display-policy.md), [ADR-0013](0013-overlay-coordinate-basis.md)

## 文脈

表示クライアントは当面 Web だが、将来 Unity / Android へ移る可能性がある。
バックエンドが特定クライアントの都合に縛られると、移行時に配信部分を作り直すことになる。

一方で開発中は「そもそもカメラが映っているか」「検出が当たっているか」を
ブラウザで直接確かめたい。配信の本線とデバッグ用の映像をどう分けるかも決める必要があった。

## 決定

- 検出結果は `/ws` の **JSON over WebSocket** を唯一の契約とする。
  bbox は **0.0–1.0 の正規化値** (原点は左上、x 右 / y 下が正)。
  ペイロードには `frame_id` / `ts` / `fps` / `source_size` / `view` / `detections` を含める。
- MJPEG の `/video` は**デバッグ専用の副系統**とする。`?annotate=0` で枠を焼き込まない
  素の映像を返し、フロントはこちらを使う。

## 理由

- **JSON over WebSocket**: Web / Unity / Android のいずれからも標準機能で読める。
  バイナリの独自プロトコルは転送量で勝るが、この規模 (15fps・最大15件) では利点が無く、
  デバッグのしやすさを大きく損なう。
- **正規化座標**: 表示側の解像度・ウィンドウサイズに依存しない。ピクセル座標で送ると、
  クロップやリサイズのたびにクライアント側で補正が必要になり、補正漏れが
  「枠だけがズレる」バグとして表面化する。
- **`view` を毎フレーム同送する**: クライアントが自前で調整値を持たずに済む。
  サーバがクランプした後の実値 ([ADR-0007](0007-viewport-crop-calibration.md)) が
  そのまま届くため、HUD 表示と実際の見た目が必ず一致する。
- **`source_size` を含める**: フロントがレターボックスを計算するために必要
  ([ADR-0013](0013-overlay-coordinate-basis.md))。既にこのペイロードで届くので追加の通信が要らない。
- **フロントが `annotate=0` を使う**: 枠は HTML 側 (`#overlay`) で描くため、映像にも
  焼き込むと同じ枠が二重に出る。さらに `d` キーで映像を消したとき、焼き込んだ枠だけが
  一緒に消えて紛らわしい。日本語ラベルの描画コストも省ける。
  `/video` を直接開く場合はページ側の枠が無いので、既定 (注釈付き) のままで二重にならない。

## 結果

- バックエンドは表示側の都合を知らずに済み、フロントを差し替えても無変更で使える。
- MJPEG のために注釈描画の経路 (PIL / cv2) を別に抱えることになり、枠を描くコードが
  サーバとフロントの2箇所に存在する。デバッグ用途に限る前提で許容している。
- `/ws` は新しい `frame_id` のときだけ送る (無駄な再送を防ぐため)。カメラが止まると
  送信も止まるので、フロント側はそれを前提に直近ペイロードで描き直している
  ([ADR-0010](0010-client-side-display-policy.md))。
