# ADR-0022: 矢印の選び替えは軸に沿った輪を回し、端で一周する

- ステータス: 承認済み
- 記録日: 2026-08-30
- 関連: [ADR-0011](0011-gaze-target-selection.md), [ADR-0012](0012-lock-tracking-by-iou.md), [ADR-0013](0013-overlay-coordinate-basis.md), [ADR-0020](0020-arrow-target-navigation.md), [ADR-0021](0021-mode-wheel-with-calibration.md)

## 文脈

[ADR-0020](0020-arrow-target-navigation.md) では、矢印は「その向きにある最も近い
検出」へ対象を移し、その向きに候補が無ければ何もしないと決めた。

実際に使うと、`→` を押し続けたときに右端で止まる。「次のものを順に見ていく」と
いう操作にならず、逆のキーへ持ち替えて戻る必要がある。

利用者から「右キーを連続で押すと次のものが選択されてほしい。選択の円を回転する
感じに」という要求が出た。

## 決定

- 矢印は**軸に沿って並べた輪**を回す。`→`/`←` は検出の中心 `x` だけを、
  `↑`/`↓` は中心 `y` だけを見る。
- 「次」とは、進む向きにある検出のうち**軸の位置が最も手前のもの**である。
  その向きに尽きたら、**反対の端**(反対向きで軸の位置が最も遠いもの)へ回り込む。
- **軸の位置が起点と厳密に等しい検出は「次」に選ばない。** 真上・真下に重なった
  物は `↑`/`↓` で拾う。
- 軸の位置が完全に並んだときだけ、もう一方の軸 → ラベルの順で一意に決める
  (`navTieLess`)。
- 円錐・減点による絞り込み(`NAV_CONE` / `NAV_CROSS_WEIGHT` / `NAV_MIN_PX`)は
  **すべて廃止**する。2次元のスコアリングは行わない。
- 距離を測らず順序だけを見るため、**正規化座標のまま**扱う。`navTarget()` は
  `viewRect()` を受け取らなくなった。ただし ADR-0011 の「距離は表示ピクセルで
  測る」は、距離そのものを使う `gazeTarget()` 側では従来どおり有効である。
- 一周したときは報せに `(一周)` を付ける。軸上に他の候補が無ければ、従来どおり
  何も起きない。
- 一周も「移動が成立した」扱いとする。固定中に矢印を押したときは、ADR-0020 の
  とおり選択中へ降格したうえで跳ぶ。
- 方向の意味(`→` は右)は変えない。

## 理由

- **円錐と減点をやめた**: 乱数配置3000件で従来方式(円錐+減点で「その向きの
  最も近い検出」を選び、行き止まりで反対の端へ跳ぶ)を検証したところ、一周は
  必ず閉じるものの、`→` を押し続けても**28.7%の検出に届かなかった**。最悪の
  例では検出9件のうち2件しか巡れず、2点間を往復するだけだった。原因は
  「行きはスコア最小・一周は距離最大」という**別々の基準で単一の勝者を選ぶ**
  ことにある。円錐の内側にいても、行きのスコアでは他の検出に負け、一周の
  距離でも他の検出に負け続ける検出が生まれ、その検出は永久に選ばれない。
  これでは「連続で押すと次のものが選択されてほしい」という要求を満たさない。
- **軸の位置だけで並べる**: 一次元の全順序にすれば、押し続ければ必ず全件を
  単調に巡って戻ってくることが構造的に保証される。予測もしやすく、「`→` は
  右へ、右端まで行ったら左端へ」と一言で説明できる。
- **同じ軸位置は次にしない**: 押した向きと動く向きを揃えるため。真上に重なった
  物を `→` で拾うと「右を押したのに上へ動いた」になる。その代わり、そうした
  検出は `↑`/`↓` で必ず拾える。
- **角度順の輪にはしなかった**: 照準まわりの角度で並べる案もあるが、机の上の
  ように高さが揃った場面では角度が 0°付近と 180°付近に固まり、`→` の順序が
  上下のわずかな差で決まって予測できない。
- **失ったもの**: [ADR-0020](0020-arrow-target-navigation.md) の「まっすぐ隣が
  斜めより優先される」という性質は成り立たなくなった。`→` は「最も近い右の
  隣」ではなく「`x` が次のもの」を選ぶため、狙って掴む操作としてはやや粗く
  なる。押し続けて視界の検出を巡れることを優先した。

## 結果

- 乱数配置3000件(検出2〜9件)で検証したところ、`→` を押し続けたときに到達
  できない検出は **0%**、閉路に入らない配置も **0件**だった。
- 軸の位置が厳密に一致する検出は、その軸の巡回には入らない。もう一方の軸で拾う。
  サーバは座標を小数5桁に丸めて配信するので (`backend/detector.py`,
  `backend/stabilizer.py`)、連続値ほどではないにせよ厳密な一致は起こりうる。
  2件の中心が x も y も完全に一致した場合、その2件は矢印では選び分けられない。
  上流で同じ物体を二重に検出したときにしか起きないので、そのときに直す。
- 見失い猶予中 (最大2秒) に矢印を押すと、起点は「見失った対象の最後の位置」に
  なる。「最後に見ていた場所から続ける」ことになるので意図どおりだが、その位置が
  視界の端だと一周が起きて反対側へ跳ぶ。`(一周)` の報せで補う。
- 調整点だった `NAV_CROSS_WEIGHT` / `NAV_CONE` / `NAV_MIN_PX` は無くなった。
  ADR-0020 に書いた「検出枠のぶれで自分自身を選び直しうる」という制約も、
  位置の近さではなく厳密な一致だけで足切りするようになったため解消した。
- `navTarget()` の戻り値が `{ det, wrapped }` であることは変わらない。呼び出し
  側は報せの出し分けにだけ `wrapped` を使う。
- ADR-0020 はこの ADR で置換する。
