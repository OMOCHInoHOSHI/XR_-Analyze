# ADR-0029: 直前のモードを次の起動へ引き継ぐ

- ステータス: 承認済み
- 記録日: 2026-08-30
- 関連: [ADR-0008](0008-calibration-persistence.md), [ADR-0010](0010-client-side-display-policy.md), [ADR-0021](0021-mode-wheel-with-calibration.md)

## 文脈

モードは起動のたびに広域鑑定から始まる (`let mode = MODE_MULTI`)。単体鑑定を
主に使う利用者は、立ち上げるたびに `m` で円盤を開いて選び直すことになる。
毎回同じ操作を繰り返させる理由がない。

## 決定

- 直前に使っていたモードを **`localStorage`** に保存し、次回の起動時に復元する。
- 保存するのは鑑定法 (単体鑑定 / 広域鑑定) だけ。**調整モードは保存しない。**
- 値が無い / 壊れている / 未知のモードIDのときは、現在の既定である広域鑑定に
  フォールバックする。

## 理由

- **`localStorage` に置いた (サーバへ保存しない)**: モードは利用者の好みであり、
  表示ポリシーとしてクライアントに閉じる
  ([ADR-0010](0010-client-side-display-policy.md))。文字サイズ (UI スケール) が
  既に同じ場所に保存されており、性質も置き場所も揃う。
- **`calib.json` ([ADR-0008](0008-calibration-persistence.md)) に混ぜなかった**:
  あちらはカメラとグラスの物理的な合わせ込みで、機材に属する値である。サーバが
  起動時に読んでカメラへ渡す。モードは画面の使い方の好みで、持ち主が変われば
  変わる。同じファイルに置くと、機材の設定と人の好みが混ざる。
- **調整モードを保存しない**: 調整は一時的な作業状態であり、終える前提のモードで
  ある。次回それで始まると、鑑定が動いていない画面から始まってしまう。
  [ADR-0021](0021-mode-wheel-with-calibration.md) で調整を円盤に載せたのは
  「入り口を揃える」ためで、常態として選ばれ続けることは想定していない。
- **壊れた値は既定へ倒す**: `localStorage` は利用者が消せるし、古い版が書いた値が
  残ることもある。読めない値で起動を止める理由はない
  ([ADR-0008](0008-calibration-persistence.md) の「読み込みに失敗しても起動は
  止めない」と同じ考え方)。値が壊れている場合だけでなく、**サイトデータを
  遮断したブラウザのように `localStorage` へのアクセス自体が例外を投げる環境**でも
  同じで、読み書きの失敗は握り潰して既定のまま動かす。モードを覚えられないことは、
  鑑定が動かないことに比べれば些細である。

## 結果

- 前回終了時のモードで立ち上がる。単体鑑定を常用するなら、起動直後から鑑定できる。
- **引き受けた制約**: ブラウザのストレージを消すと既定 (広域鑑定) に戻る。
- **引き受けた制約**: 端末やブラウザをまたいでは引き継がれない。サーバに置いていない
  以上、これは避けられない。
