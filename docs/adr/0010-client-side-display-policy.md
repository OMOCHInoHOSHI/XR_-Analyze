# ADR-0010: 鑑定法と鑑定の固定はクライアント側の表示ポリシーとして閉じる

- ステータス: 承認済み
- 記録日: 2026-08-18
- 関連: [ADR-0002](0002-detection-streaming-contract.md), [ADR-0006](0006-single-background-pipeline.md), [ADR-0007](0007-viewport-crop-calibration.md), [ADR-0011](0011-gaze-target-selection.md), [ADR-0012](0012-lock-tracking-by-iou.md)

## 文脈

鑑定法 (単体鑑定 / 広域鑑定) の切り替えと鑑定の固定は、「どの検出を描くか」の話であって
「何を推論するか」ではない。これをサーバの状態にするか、クライアントに閉じるかで、
複数クライアントが繋がったときの挙動が変わる。

一方でズーム / 切り抜き位置は、映像・推論・検出座標のすべてに影響する
([ADR-0007](0007-viewport-crop-calibration.md))。同じ扱いにはできない。

## 決定

- **鑑定法の切り替え・鑑定の固定・表示件数の絞り込み (広域鑑定は最大10件) は、
  フロント (`frontend/index.html`) の表示ポリシーとして完結させる。**
  サーバは従来どおり信頼度上位 `MAX_DET` 件 (既定 15) を配信し、`/ws` の出力は変わらない。
- **ズーム / 切り抜き位置はサーバ側の状態とする。** フロントは差分を投げるだけで、
  確定値は `/ws` の `view` で受け取る。

## 理由

- **表示ポリシーをサーバに持たせない**: 複数のクライアントが繋がったときに互いの状態を
  踏み合う。「推論内容に影響しないものはサーバの状態にしない」という線引きにした。
- **調整値はサーバに持たせる**: 逆にこちらは映像そのものを動かすため、サーバ側でなければ
  クライアント間で整合が取れない。フロントが自前で値を持たないので、クランプ後の実値と
  HUD 表示が必ず一致するという利点もある ([ADR-0002](0002-detection-streaming-contract.md))。

## 結果

- フロントを差し替えても、表示ポリシーの実装だけを持っていけばよい。
- **制約**: 検出が `MAX_DET` を超える場面では、信頼度が低い物体が画面中央にあっても
  サーバ側で落ちている場合がある ([ADR-0006](0006-single-background-pipeline.md))。
  単体鑑定でもその物体は拾えないので、必要なら `MAX_DET` を増やす。
- `/ws` は新フレームのときだけ送るため、カメラが止まると表示も止まる。直近ペイロードを
  `lastPayload` に保持し、`repaint()` で描き直せるようにしている。一時メッセージの
  期限切れや固定の猶予切れも、この仕組みで新フレーム無しに反映される。
- `POST /calib` の一時的な失敗は握りつぶす (次のキー操作で取り戻せるため)。一方
  `POST /calib/save` の結果は調整のやり直しに直結するので HUD に出す。
