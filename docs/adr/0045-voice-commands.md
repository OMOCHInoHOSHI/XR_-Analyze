# ADR-0045: 音声コマンドは Vosk で言葉を絞って PC の中で聞き取り、判断はブラウザで行う

- ステータス: 承認済み
- 記録日: 2026-11-23
- 関連: [ADR-0010](0010-client-side-display-policy.md), [ADR-0019](0019-key-binding-policy-v2.md), [ADR-0021](0021-mode-wheel-with-calibration.md), [ADR-0024](0024-llm-object-explanation.md), [ADR-0026](0026-voicevox-character-voice.md), [ADR-0032](0032-prompt-shutdown.md), [ADR-0042](0042-windows-exe-packaging.md)

## 文脈

XR グラスを掛けたままキーボードを探って操作するのは手間なので、声で操作したいという
要求が出た。求められた言葉は次のとおり。

| 言葉 | 動作 |
|---|---|
| 「モード変更」 | モードの円盤を開く |
| 円盤を開いている間の「たんたいかんてい」「いち」 / 「こういきかんてい」「に」 | 単体鑑定 / 広域鑑定に切り替える |
| 単体鑑定中の「鑑定」 | 鑑定を行う |
| 鑑定ウィンドウを開いている間の「とじる」 | ウィンドウを閉じる (後から追加) |
| 円盤を開いている間の「とじる」 | 円盤を閉じる (後から追加) |
| いつでも「終了」 | アプリを終了する |

制約と前提:

- 鑑定文の生成 (Ollama) と読み上げ (VOICEVOX) はすでに PC の中だけで動いている
  ([ADR-0024](0024-llm-object-explanation.md), [ADR-0026](0026-voicevox-character-voice.md))。
- Mac と Windows の両方で動かす。Windows では exe にもまとめる
  ([ADR-0042](0042-windows-exe-packaging.md))。
- 検出 (YOLO) が GPU を使っている。
- 「に」のような 1 音だけの言葉がある。話した内容を書き起こす種類の音声認識は、
  1 音の言葉をほぼ取れない。
- 鑑定士の読み上げはスピーカーから流れ、マイクが拾いうる。鑑定文には「鑑定」が
  よく出てくる。

## 決定

- 認識には **Vosk** (Kaldi 系の、ネット不要な音声認識) の小さい日本語モデル
  `vosk-model-small-ja-0.22` を使い、**認識する言葉を 8 つに限定する** (grammar 指定)。
  モデルは初回の起動時に取得して `DATA_DIR` に置く。
- マイクの取得と認識はサーバ (`backend/voice.py`) が行い、聞き取ったコマンドと
  マイクの音量を WebSocket `/voice` でブラウザへ送る。**どの場面でどのコマンドを
  受け付けるか**はブラウザ (`frontend/app.js`) が決める。
- 認識結果が**ちょうど 1 つのコマンドだけ**のときにだけ受け付ける。前後に何か
  付いていたら捨てる。
- **鑑定ウィンドウが開いている間は「とじる」「終了」以外を受け付けない。**
- 「終了」は `POST /shutdown` でサーバを止め、画面には終了の表示を出す。
  この PC (ループバック) からの要求だけを受け付ける。
- 鑑定盤に「音声」の行を足し、マイクの音量を**波形**で出す。聞き取って受け付けると
  線が光る。

細かい仕様は [docs/voice-recognizer.md](../voice-recognizer.md) にまとめた。

## 理由

### 認識エンジン

| 候補 | 採らなかった理由 |
|---|---|
| Whisper 系 (faster-whisper / whisper.cpp) | 書き起こし向けで、言葉を限定できない。1 音の「に」に弱く、無音で「ご視聴ありがとうございました」と出る幻聴がある。GPU を YOLO と取り合う |
| ReazonSpeech | 日本語の精度は高いが書き起こし向けで、言葉を限定できない。重い |
| Julius | 日本語のコマンド認識には向くが、Python からは別プロセスを立てて通信する必要があり、Windows で動かすまでが手間。更新も止まり気味 |
| Picovoice Rhino | コマンド認識に特化していて用途は最も合うが、アカウント登録と AccessKey が必要で、無料枠に制限がある |
| Web Speech API (ブラウザ) | ネットが必須。言葉を限定できない。Chrome と Edge でしか使えない |
| クラウド (Google / Azure / AWS) | ネットが必須で、キーの管理と従量課金が要る |
| Windows 標準 (SAPI) | Windows でしか動かない |

Vosk は「言葉を限定できる」「ネット不要」「Mac と Windows の両方」「CPU だけで軽い」
「pip で入って Python から直接呼べる」「Apache 2.0 で登録や課金が要らない」を
すべて満たす唯一の候補だった。

### 言葉の書き方

Vosk の日本語モデルは語彙が単語単位なので、grammar も単語の区切りで書く
(「たんたいかんてい」は語彙では「単体 鑑定」)。8 つの言葉はすべて語彙にあることを
確かめた。「いち」「に」「とじる」は仮名と漢字 (一・二・閉じる) の両方が語彙にある。
両方を入れると確信度が半分ずつに割れたため、片方に絞った。

Windows 標準の合成音声 (Haruka) で 8 語と関係ない会話・読み上げ文を作って比べた:

| grammar | 8 語 | 「これは何でしょうか」 | 読み上げ文 |
|---|---|---|---|
| 仮名 (いち・に・とじる) | 8/8 | `[unk] [unk]` | `[unk] [unk] 鑑定 [unk]` |
| 漢字 (一・二・閉じる) | 8/8 | `[unk] 二 [unk]` | `[unk] [unk] 二 [unk]` / `鑑定 [unk]` |

漢字の「二」は普段の会話から拾われやすかったので、仮名を採った。

### 「ちょうど 1 つのコマンド」だけを受け付ける

読み上げをマイクが拾うと、上の表のように `[unk] [unk] 鑑定 [unk]` が出る。結果の中に
コマンドの語を探すやり方だと、これを「鑑定」と取ってしまう。前後に `[unk]` や別の
語が付いていたら捨てれば、文の途中のコマンド語では動かない。grammar に `[unk]` を
入れているのは、関係ない会話が無理にコマンドへ当てはめられず `[unk]` になるようにするため。

### 区切りを自前で補う (SETTLE_SEC)

関係ない会話のあと 1 秒の無音を挟んでコマンドを言うと、Vosk が会話の終わりで区切らず、
`[unk] いち` や `[unk] [unk] [unk] 終了` のようにつながって捨てられた。区切りの
待ち時間を変える設定は、pip で入る vosk 0.3.45 には無い。

そこで、途中の認識結果 (partial) が `SETTLE_SEC` の間変わらなければ、発話が
終わったとみなして確定させる。同じ音声で待ち時間を比べた:

| SETTLE_SEC | 8 語 | 誤って受け付けたもの |
|---|---|---|
| 0.3 秒 | 7/8 (「広域 / 鑑定」の間で切れて `広域 [unk]`) | なし |
| 0.5 秒 | 8/8 | なし |
| 0.7 秒 | 8/8 | なし |

間を取って 0.6 秒にした。短いと言葉の途中で切れ、長いと反応が遅れる。

### 判断をブラウザで行う

モード・円盤・鑑定ウィンドウ・固定の状態は、キー操作と同じくブラウザだけが持っている
([ADR-0010](0010-client-side-display-policy.md))。サーバで判断するには状態をサーバへ
写す必要があり、二重管理になる。サーバは「何と聞こえたか」だけを送る。

### 鑑定ウィンドウ中は「とじる」「終了」だけ

最初は「読み上げ中だけ『鑑定』を無視する」案だったが、次の理由で変えた。

- キー操作も、鑑定ウィンドウが開いている間は閉じる操作 (Enter / Esc) しか効かない
  ([ADR-0019](0019-key-binding-policy-v2.md))。声もそれにそろえると覚えることが減る。
- 読み上げはウィンドウが開いている間に流れるので、範囲をウィンドウで切れば
  読み上げの声による誤動作をまとめて防げる。

### 固定中の「鑑定」は照準の対象へ移す

Enter は固定中に押すと解除になる。声で同じにすると、「とじる」で窓を閉じても固定が
残り、次の物を見て「鑑定」と言うと解除されるだけで、声だけでは次の鑑定に進めない。
そこで、ウィンドウを閉じて固定が残っている状態の「鑑定」は、照準が今狙っている対象へ
固定を移して鑑定し直す。「鑑定 → とじる → 次を見る → 鑑定」が声だけで繰り返せる。

### 声で開いた円盤は 6 秒

キーで開いた円盤は 3 秒で自動で閉じる ([ADR-0019](0019-key-binding-policy-v2.md))。
声では、話し終えてから認識されるまでに `SETTLE_SEC` を含めて 0.3〜1 秒かかる。3 秒では
「たんたいかんてい」を言い切る前に閉じることがあるので、声で開いたときだけ 6 秒にした。

### 終了

ブラウザのタブはページの側から閉じられない (スクリプトで開いた窓以外)。サーバを止め、
画面全体に「終了しました」と出して終える。止め方は Ctrl+C と同じ経路
([ADR-0032](0032-prompt-shutdown.md)) で、`_shutting_down` を立ててから uvicorn の
`should_exit` を立てる。exe ではプロセスが終わるとコンソール窓も閉じる。

`HOST=0.0.0.0` で公開している場合に、同じネットワークの他の機器からアプリを止め
られないよう、`/shutdown` はループバックからの要求だけを受け付ける。

### タブを 2 つ開いた場合

聞き取った結果は、最後に開いた `/voice` の接続にだけ送る。全部に送ると、開いている
タブがそれぞれ同じ操作をする。古いタブには「別のタブで使用中」と出す。

### 波形

🎤 の絵ではなく、マイクの音量で振れる波形にした。自分の声がマイクに入っているかが
その場で目で分かり、反応しないときにマイクの問題か認識の問題かを切り分けられる。
見た目は見本ページで合意した (両端は平ら、中央の 9 頂点だけが上下に交互に振れる、
角を丸めない)。

## 結果

- 声で、円盤の開閉・鑑定法の切り替え・鑑定・鑑定ウィンドウを閉じる・終了ができる。
  キー操作はすべてそのまま使える。
- 追加の依存は `vosk` と `sounddevice`。どちらも Windows / macOS 用の wheel に
  ネイティブライブラリが入っている。exe には `libvosk.dll` を明示して同梱する
  (パッケージのフォルダから名前で読まれ、PyInstaller の解析では拾われないため)。
- **引き受けた制約**: 初回の起動で約 50MB のモデルを取得する。ネットが無い環境では
  `VOSK_MODEL` に手で置く。モデルは展開後 95MB あり、取得元から同じものが取れるので
  リポジトリにはコミットしない。
- **引き受けた制約**: 認識の確認は合成音声 (Windows の Haruka) で行った。人の声・
  マイクの距離・部屋の雑音での精度は、実際に使って確かめる必要がある。開発機の
  Web カメラのマイクは無音時に -88 dBFS と非常に小さく、音量の表示 (-60〜-10 dBFS を
  0〜1 に対応) が振れにくいことがありうる。
- **引き受けた制約**: 読み上げ文の中に「とじる」「終了」だけが単独で区切られて
  聞き取られると、鑑定ウィンドウ中でも閉じる・終了が起きうる。前後に別の語が付く
  限りは捨てるので、試験した文では起きなかった。
- **引き受けた制約**: 「終了」には確認を挟まない。保存していない調整値は、Ctrl+C で
  止めたときと同じく失われる。
- 言葉を増やすときは `backend/voice.py` の `PHRASES` に足し、`frontend/app.js` の
  `runVoiceCommand` に動作を書く。語彙に無い語は grammar に入れても Vosk が黙って
  無視するので、モデルの `graph/words.txt` に載っているかを先に確かめること。
