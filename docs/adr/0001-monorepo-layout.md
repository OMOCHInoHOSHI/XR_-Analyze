# ADR-0001: バックエンドとフロントを1リポジトリでディレクトリ分離する

- ステータス: 承認済み
- 記録日: 2026-08-18
- 関連: [ADR-0002](0002-detection-streaming-contract.md), [ADR-0010](0010-client-side-display-policy.md)

## 文脈

バックエンド (Python: カメラ取得 + YOLO 検出) とフロント (Web) は、検出座標の定義と
WebSocket のスキーマという同じ契約を共有する。一方で、表示クライアントは当面 Web だが
将来 Unity / Android へ置き換える可能性がある。

リポジトリを分けるか、1つにまとめるか、まとめるならどう配置するかを決める必要があった。

## 決定

単一リポジトリに `backend/` と `frontend/` をディレクトリ分離して置く。

## 理由

- **別リポジトリにしない**: 契約 (座標系・WS スキーマ) を共有しているため、
  仕様を変えるたびに2つのリポジトリを同期させる手間が生じる。この規模では
  同期コストのほうが分離の利益を上回る。
- **同一ディレクトリに混ぜない**: フロントを Unity / Android に差し替えるとき、
  どのファイルがフロント固有なのか切り分けられなくなる。ディレクトリで分けておけば
  `frontend/` を丸ごと別のプロジェクトに置き換えても `backend/` は無変更で済む。

## 結果

- `backend/` は「クライアント非依存を保つ」責務を負う。フロント固有の都合を
  バックエンドへ持ち込まない方針は [ADR-0010](0010-client-side-display-policy.md) で明文化した。
- Python の `.venv` とモデル重み (`*.pt`) がリポジトリ直下に同居するため、
  `.gitignore` での除外管理が必要になる。
