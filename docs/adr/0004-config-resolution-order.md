# ADR-0004: 設定は環境変数で上書きし、調整値は 環境変数 > 保存ファイル > 既定値 で解決する

- ステータス: 承認済み
- 記録日: 2026-08-18
- 関連: [ADR-0005](0005-camera-selection.md), [ADR-0008](0008-calibration-persistence.md), [ADR-0009](0009-inference-device-selection.md)

## 文脈

カメラ番号・モデル・しきい値・ポートなどは、コードを触らずに切り替えたい。
さらにズームと切り抜き位置はサーバ稼働中に調整して保存する
([ADR-0008](0008-calibration-persistence.md)) ため、「保存済みの値」と
「その場限りの上書き」の両方が成立する必要がある。

## 決定

- 設定は**環境変数で上書きする方式**に統一し、`backend/config.py` の 1 ファイルに集約する。
- ズーム / オフセットの解決順序は **環境変数 > 保存ファイル (`calib.json`) > 既定値**。
- 不正な値は「指定が無かったもの」として扱い、起動は止めない。

## 理由

- **専用の設定ファイル形式を作らない**: 起動コマンドに 1 行足すだけの一時的な試行
  (`CAM_ZOOM=1.5 python3 -m backend.server`) がしにくくなる。環境変数なら CLI から
  自然に上書きでき、README の一覧表とそのまま対応が取れる。
- **明示指定を最優先にする**: [ADR-0005](0005-camera-selection.md) の `CAM_INDEX` と同じ方針。
  「明示したのに保存値が勝つ」という驚きを無くす。保存値はあくまで
  「明示指定が無いときの既定値」として働く。
- **不正値で落とさない**: 設定の入力ミスでサーバが起動しなくなるのは復旧が重い。
  既定値で立ち上げたほうが、映像を見ながら直せる。

## 結果

- 全設定が `config.py` に集まるため、「今どの値で動くか」をコードから 1 箇所で読める。
- 一方で実行時の確定値は環境変数と `calib.json` の両方に依存するため、起動時に
  確定値 (`[calib] ... 初期値: CAM_ZOOM=... `) をログへ出力して補っている。
- `CAM_INDEX` は「環境変数で明示されたか」を区別する必要があるため、
  `CAM_INDEX_ENV`(未指定なら `None`) と、フォールバック込みの `CAM_INDEX` の
  2 つを公開している。
