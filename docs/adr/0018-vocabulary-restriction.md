# ADR-0018: 検出語彙を実在の物体だけに絞る

- ステータス: 承認済み
- 記録日: 2026-08-28
- 関連: [ADR-0002](0002-detection-streaming-contract.md), [ADR-0003](0003-label-localization.md), [ADR-0012](0012-lock-tracking-by-iou.md), [ADR-0016](0016-mask-free-fast-inference.md)

## 文脈

`yoloe-11l-seg-pf.pt` の内蔵語彙は **4585 語**あり、その中に物体ではない語が
大量に含まれている。`stack` `activity` `accident` `academy` `darkness`
`computer room` `street scene` `reflection` `love` などである。

これらが実在の物体名と競合し、単体鑑定で出る最上位ラベルがフレームごとに
入れ替わる。実機フレーム 40 枚 (机の上、80ms 間隔、ほぼ同じ景色) で測ると、
最上位ラベルは `stack` 21 / `monitor` 9 / `computer chair` 6 / `laptop` 2 …
と割れ、隣接フレーム間の一致は 38% しかなかった。同じ入力に対しては 40/40 で
決定的なので、これはモデル本来の揺れである。暗い部屋にカメラを向けると
`darkness` (ダークネス) が信頼度 0.92 で最上位に出る。

[ADR-0012](0012-lock-tracking-by-iou.md) の固定追従も、時系列の安定化層も、
この揺れを後段で抑えるための仕組みだった。語彙そのものを断てば根本で減らせる。

## 決定

- 語彙を **LVIS 1203 カテゴリ (同義語込み) に一致するモデル語彙だけ**に絞る。
  実測で 4585 語 → **1054 語**。
- 設定は `VOCAB` で、既定は `auto`。
  - `auto` : クラス数が 1500 以上のモデルのときだけ `lvis` として振る舞う
  - `lvis` : 常に LVIS で絞る
  - `all` : 絞らない (従来どおり)
  - パス : 1 行 1 語のファイルを語彙とする
- 実現方法は **語彙ヘッドの行の切り出し**。プロンプトフリーのモデルはクラス名の
  埋め込みが `lrpc[i].vocab` の重みの行として焼き込まれているので、行を抜き出せば
  残したクラスのスコアは絞り込み前と完全に同じになる。
- 切り詰められないモデル向けに、後処理でスコアの行を選ぶ経路も持つ。結果は同じで、
  行列積が小さくならないぶん速くならないだけ。
- 配信する `class_id` は**元の番号のまま**返す
  ([ADR-0002](0002-detection-streaming-contract.md) の契約を変えない)。
- `CLASSES` で語彙を明示している場合は絞らない。利用者が挙げた語がその語彙である。

## 理由

- **「意味の近い単語を統合する」では効かなかった。** 当初の見立ては
  `motorbike`/`motorcycle` のような同義語が競合しているというものだった。
  クラス埋め込みのコサイン類似度でクラスタリングして代表 1 語に寄せる案を実測したが、
  隣接フレームの最上位ラベルの入れ替わりは 24 回 → 23 回 (閾値 0.95)、
  23 回 (閾値 0.90) とほとんど変わらなかった。効いたのは同義語の統合ではなく
  **物体でない語の除去**である (24 回 → 4 回、安定化層通過後は 6 回 → 0 回)。
- **LVIS を基準にする理由**: 実在の物体だけを人手で選んだリストであり、
  本リポジトリは既にその対訳辞書 (`labels_ja_lvis.py`) を持っている。
  README が謳う「LVIS 等 1200+ の語彙」とも一致する。判定基準を自前で作るより、
  出所のはっきりした既存のリストに乗る方が後から検証しやすい。
- **機械的な語彙の拡張は採らなかった。** LVIS とモデルは呼び名が違うことがあり
  (LVIS `laptop computer` / モデル `laptop`)、そのままでは 164 カテゴリを取りこぼす。
  語単位の包含で拾い直す案を 2 通り実測したが、どちらも `bar` `beach` `food`
  `clothing` `darkness` のような汎用語まで一緒に拾ってしまい、入れ替わりが
  4 回 → 14 回へ悪化した。取りこぼしは**手で足す**方が結果が良い。
  そのために `python3 -m backend.vocab` で現在の語彙を書き出せるようにしてある。
- **`auto` を既定にする理由**: COCO 80 クラスや `CLASSES` の指定はすべて実在の
  物体なので、絞ると取りこぼすだけで得が無い。混ざり物があるのはオープン語彙の
  内蔵辞書だけなので、そこにだけ効かせる。
- **`class_id` を元のまま返す**: 切り詰めると番号が詰まるが、配信する番号が
  設定次第で変わるとクライアントが壊れる。対応表を持って元へ戻す。

## 結果

- 実機フレーム 40 枚での最上位ラベル: `stack` 21 / `monitor` 9 / … だったものが
  **`monitor` 40/40** になった。隣接フレーム間の入れ替わりは生で 24 回 → 4 回、
  安定化層を通した後は 6 回 → **0 回**。
- 副次的に速くなった。語彙ヘッドの行列積と出力テンソルが小さくなるため、
  実機フレームで 91.0ms → 81.9ms (1.11 倍)。
- **語彙は狭くなる。** 4585 語 → 1054 語なので、LVIS に無い物体
  (`laptop` `humidifier` `smartphone` など) は名前が付かないか、別の許可語へ
  付け替わる。実測でも `ノートパソコン` が消えた。狭すぎる場合は
  `python3 -m backend.vocab > my_vocab.txt` で書き出し、必要な語を足して
  `VOCAB=my_vocab.txt` を指定する。
- 絞り込みは[高速推論経路](0016-mask-free-fast-inference.md)の中で行うため、
  `FAST_INFER=0` では効かない。その場合は起動時に注意を出す。
- 語彙を絞ると fp16 の揺れの影響も小さくなるはずなので、
  [ADR-0016](0016-mask-free-fast-inference.md) で見送った CoreML(ANE) を
  再検討する条件が変わる。`backend/compare_coreml.py` で測り直せる。
