# ADR-0030: 円盤は矢印の向きと同じ向きに回す

- ステータス: 置換 ([ADR-0031](0031-wheel-layout-restored.md) による)
- 記録日: 2026-08-30
- 関連: [ADR-0021](0021-mode-wheel-with-calibration.md), [ADR-0023](0023-rotating-mode-wheel.md)

## 文脈

[ADR-0023](0023-rotating-mode-wheel.md) で、円盤はカーソルではなく盤そのものを
回して選ぶ形にした。ただし**どちら向きに回るか**は決めていなかった。

実装は、項目を 12時から時計回りに並べ (12時=壱 / 4時=弐 / 8時=参)、`→` を押すと
次の項目を 12時へ持ってくるために盤を**左回り**に回していた。押した向きと盤の
動く向きが逆になる。利用者から「時計回りにしてほしい」という要求が出た。

## 決定

- `→` / `↓` で盤が**右回り (時計回り)** に回り、次の項目が 12時の指標へ来る。
  `←` / `↑` は左回りで前の項目へ戻る。
- そのために項目の配置を逆順にする (12時=壱 / 8時=弐 / 4時=参)。
- カーソルの進む順序 (壱 → 弐 → 参) と、数字キーによる即確定
  ([ADR-0019](0019-key-binding-policy-v2.md)) は変えない。

## 理由

- **押した向きと盤の動く向きを揃える**: `→` を押して盤が左へ回るのは、
  つまみを右へ回したのに左へ動く道具と同じで、操作のたびに引っかかる。
  [ADR-0023](0023-rotating-mode-wheel.md) が回転角を剰余に畳まず足し引きで持つ
  理由として挙げた「押した向きと盤の回る向きが食い違って見える」問題と、
  性質は同じである。あちらは一周したときの話で、こちらは常に起きていた。
- **配置を逆順にして回転の向きを変えた (カーソルの向きを変えるのでなく)**:
  `→` で前の項目へ戻る形にすれば盤は右回りになるが、それでは「進む」と「戻る」が
  入れ替わり、数字キーの並び (壱=1 / 弐=2 / 参=3) とも食い違う。配置のほうを
  変えれば、順序も数字キーもそのままで向きだけが直る。
- **`MODES` から配置を導く性質は保つ**: 配置角の符号を変えるだけなので、項目を
  足し引きしても配置が追従する [ADR-0021](0021-mode-wheel-with-calibration.md) の
  性質はそのまま残る。

## 結果

- `→` を押すと盤が時計回りに回り、次の項目が 12時へ滑り込む。
- 盤の上での並びは反時計回り (12時=壱 / 8時=弐 / 4時=参) になる。順序を盤の
  見た目から読むより、指標に来た項目を読む使い方なので、実用上の不都合はない。
- **引き受けた欠点**: [ADR-0023](0023-rotating-mode-wheel.md) の記述にある
  「12時から時計回りに等間隔」という配置の説明は、この ADR で反時計回りに変わる。
  コード上のコメントもあわせて直す。
